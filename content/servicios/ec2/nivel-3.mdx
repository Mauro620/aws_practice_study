Una sola instancia en una sola AZ es un prototipo, no una arquitectura. En producción las cosas se distribuyen, se replican y se reemplazan solas. Acá entra el resto de la familia.

#### La arquitectura de alta disponibilidad estándar

```
                    Internet
                       │
            ┌──────────▼──────────┐
            │   ALB (Application  │
            │   Load Balancer)     │
            └─────┬────────┬───────┘
                  │        │   (2+ subredes públicas,
                  │        │    una por AZ)
                  ▼        ▼
            ┌─────────┐  ┌─────────┐
            │ Insta-  │  │ Insta-  │
            │ ncia    │  │ ncia    │    ASG: mantiene N instancias
            │ EC2     │  │ EC2     │    entre min y max
            └────┬────┘  └────┬────┘
                 │            │      (subredes privadas, una por AZ)
                 ▼            ▼
            ┌────────────────────────┐
            │     RDS Multi-AZ       │   primaria + standby
            └────────────────────────┘
```

El ALB, el Auto Scaling Group y el Launch Template del diagrama tienen su propio módulo: cómo se reparten el tráfico, cuándo crecen y cómo se reemplazan las instancias está en [Elasticidad](/servicios/elasticidad).

#### Modelos de compra, uno por uno

| Modelo | Descuento vs. On-Demand | Compromiso | Cuándo conviene |
| --- | --- | --- | --- |
| **On-Demand** | 0 % | Ninguno | Cargas impredecibles, dev, pruebas, primer despliegue |
| **Savings Plans** | Hasta 72 % | 1 o 3 años de gasto por hora | Cargas estables; **más flexible que las RI**, aplica entre familias y regiones |
| **Reserved Instances** | Hasta 72 % | 1 o 3 años de un tipo específico | Cargas totalmente predecibles; ya casi reemplazadas por Savings Plans |
| **Spot Instances** | **Hasta 90 %** | Ninguno, pero AWS puede reclamar la instancia con **2 minutos de aviso** | Batch, CI/CD, renderizado, ML training — todo lo que tolere interrupciones |
| **Dedicated Host / Instance** | Recargo | Hardware físico dedicado | BYOL, licencias por core, macOS, cumplimiento normativo |

> La combinación inteligente es: **un ASG con la base en Savings Plans (el piso de carga estable) + Spot Instances para los picos**. El ahorro exacto depende de qué proporción de la carga cubrís con cada modelo — no hay una cifra única del curso para la combinación, pero cada pieza sola llega hasta el 72 % (Savings Plans) o el 90 % (Spot) frente a On-Demand puro. Metele números propios en el [comparador de costos EC2](/herramientas/comparador-costos).

#### Cómo encajan los demás componentes del nivel

| Componente EC2 | Relación con la arquitectura |
| --- | --- |
| **AMI** | Cambiarla en el Launch Template cambia todas las instancias futuras. Es la palanca para desplegar una nueva versión |
| **Tipo de instancia** | El ASG lo respeta; cambiar el tipo en el Launch Template requiere terminar y recrear instancias (no en caliente) |
| **User Data** | Se ejecuta en cada nueva instancia que el ASG lance. Es el lugar para instalar paquetes y arrancar servicios |
| **Rol IAM** | Lo lleva cada instancia creada por el ASG, igual que las manuales |
| **Elastic IP** | No se usa acá: si la instancia cambia, la IP pública la reemplaza el ALB, que es el punto estable |
